# 09 · 게임 화면 배치(A안 · 무대 우선 + 바텀시트 가방)

네이티브 앱(native/App) 게임 화면의 세로 배치 · 도트 디자인 토큰 · 비교용 개발자 스위치. 웹판(web/index.html)은 그대로다.

## 배치

| | 접힘(전투) | 펼침(정리) |
|---|---|---|
| 무대 | 화면의 약 63%(위 안전 여백 포함 · 340~620pt) + 시트가 남기는 높이 | 약 34%(200~340pt) + 시트가 남기는 높이(18 Pro 약 40%) |
| 장면 폭 | 무대 비율대로 장면 높이 270px 을 꽉 채운다(18 Pro 약 222px) | 넓어진다(약 456px — 싸움이 다 보인다) |
| 시트 | 머리(손잡이) + 엿보기 띠(글 줄 + 콤보 카드 한 줄) + 엄지 줄 | 머리 + 가방 6×4(폭을 다 씀 · 칸 약 63pt) + 작은 가로 보관함 띠 + 엄지 줄 |

- 높이는 `PlayGeometry`(Game/PlayScreen.swift)가 화면 높이 비율 + 최소 · 최대로 정한다(874pt 에 박지 않음). 시트 최소: 접힘 214pt · 펼침 380pt.
  시트가 내용보다 크면 남는 높이는 무대로 돌린다(시트 안 빈 자리 없게):
  접힘 = 머리 50 + 엿보기 띠 최대 148(글 16 + 4 + 카드 128) + 8 + 엄지 80 + 6 · 펼침 = 머리 50 + `BagGridView.sheetPreferredHeight`(폭을 다 쓰는 칸 + 보관함 띠 + 엄지 줄).
  아래 값은 안전 여백 안 무대 높이(위 여백 별도).
  - iPhone SE(375×667 · 위 20): 접힘 무대 400 · 시트 247 · 엿보기 띠 103(카드 83 — 낮은 카드: 이름 한 줄) / 펼침 무대 206 · 가방 칸 52pt · 보관함 칸 35pt
  - iPhone 18 Pro(402×874 · 위 62): 접힘 무대 488 · 시트 324 · 띠 146(카드 126) / 펼침 무대 292(예전 235 — 남던 55pt) · 칸 63pt · 보관함 칸 37pt
  - iPhone Air(420×912 · 위 68 가정): 접힘 무대 518(띠 최대 148 · 남는 16pt 는 무대로) / 펼침 무대 316 · 칸 64pt · 보관함 칸 39pt
- 무대 위 HUD
  - 캔버스(웹 drawUI): 노선도 · 남은 시간 막대 · 기술 줄 · 연타 · 초상 · 체력 · 필살 게이지 — 새 배치에서만 `HUDFrame.hudScale`(작게) ·
    `hudTop`(위 SwiftUI 줄 자리) · `scoreOutside`(점수는 SwiftUI)를 준다. 모두 nil 이면 웹 그대로라 HUD 대조 테스트는 바뀌지 않는다.
    hudScale 은 HUD 1px ≈ 1.45pt 를 목표로 하고, 노선도 줄이 오른쪽 위 점수 묶음 앞에서 끝나게 역 수에 맞춰 더 줄인다.
  - SwiftUI(PlayHUD): 왼쪽 위 역 이름(정리 중이면 '정리 중 · 0.2×' 칩) · 오른쪽 위 점수 · '남은 초 · 적 수'(정리 단계엔 숨김) · 일시정지(44pt)
- 장면 폭: `CameraDirector.visibleWidth`(앱이 무대 뷰 비율로 매 프레임) · `simViewWidth`(360). 다르면 시뮬레이션 카메라 창의 가운데를 그대로 두고
  자르며, 좁을 때는 주인공이 가장자리 밖으로 나가지 않게 민다. 시뮬레이션 `SimConfig.viewWidth` 는 360 그대로(규칙 불변).
- 시트 손짓은 머리(손잡이) 칸에서만: 위로 끌기 = 펼침 · 아래로 = 접힘 · 누르기 = 바꿈. 엿보기 줄을 눌러도 펼친다. 타일 끌기와 겹치지 않는다.
- 필살(150×80pt)은 두 상태 모두 오른쪽 아래 같은 자리. 정리 단계에선 같은 자리가 '출발 ▶'.
- 정리 단계(`arrange`)에 들어가면 시트를 펼쳐 두고, 나가면 (손으로 연 게 아니면) 접는다.
- 정리 남은 초는 **'출발 ▶' 단추 한 곳**에만: 둘째 줄 'n초 뒤 자동'(Auto in ns). 가방을 만지면(웹 arrTouched — 자동 출발이 멈춘다)
  '준비되면 눌러요'(Tap when ready). 무대 오른쪽 위 남은 초 줄은 정리 단계에 숨기고, 시트 머리 안내는 '끌어 옮기고 돌려 가방 손보기'.
  예전 배치(행동 줄 '정리 시간 n초 — …')는 그대로.

### 매점(새 배치 · Game/PlayScreen.swift `ShopPanel`)
- 무대 자리(위 안전 여백 아래 ~ 시트 머리 위)에만 가죽 판을 띄운다 — 시트 머리 · 다이내믹 아일랜드 · 홈 막대와 겹치지 않는다.
  어둡게 막은 화면 전체(시트도 못 누름 — 예전 매점 덮개와 같게). 매점에 들 때 시트가 펼쳐져 있으면 접는다(무대가 넓어야 카드가 들어간다).
- 머리 = '역 매점'(22pt) + 토큰 · 안내 한 줄 · 카드 셋(PixelButton 판 — 이름 · ★ · 옵션 · 설명) · 아래 단추 줄
  '새로고침 ⓣ2' · '각인 ⓣ4' · '지나가기'(놋쇠) — 모두 PixelButton 44pt 이상 · 폭 균등. 카드가 넘치면 카드만 굴린다.
- 예전 배치는 `ShopScreen`(GameView.swift) 그대로. 매점은 캔버스(BBPresentation HUD)가 그리지 않는다 — HUD 대조 테스트와 무관.

### 펼친 동안 시간 느리게(규칙은 그대로)
웹 규칙 'bagTouch': 전투 중 가방을 만지면 `bagSlowT = 0.6` 동안 시간 0.2배(BBSim `World.bagTouch` · `frame()`).
예전 배치는 가방을 만지는 동안 BagController 가 0.25초마다 `SimIntent.bagTouch` 를 보낸다. 새 배치는 시트가 펼쳐져 있으면
GameSession.frame 이 같은 의도를 0.25초마다 보낸다(전투 중 · 정리 단계 아님 · 메뉴 닫힘일 때만). 그래서 배율은 목업의 0.3배가 아니라
규칙 값 0.2배이고, 칩도 '0.2×'로 적는다. 정리 단계에선 보내지 않는다 — 보내면 웹 `arrTouched` 가 켜져 정리 타이머가 멈춘다.
표시는 캔버스의 웹 테두리 · '정리 중 · 시간 느림' 글자 + SwiftUI 칩 · 옅은 청록 막.

### 가방 시트(BBUI BagGridView `layoutStyle = .sheet`)
- 머리줄(제목 · 안내 · 토큰)은 SwiftUI 시트 머리가 그린다. 돌리기 · 되돌리기 · 버리기(끌어 놓는 자리)는 아래 엄지 줄,
  오른쪽 `thumbReserve` 폭은 비워 두고 SwiftUI 필살 단추를 얹는다.
- 보관함은 규칙상 2×4 그대로다. 시트에서는 그리기만 전치해(보관함 칸 (x, y) ↔ 화면 (y, x)) 가방 아래 가로 4×2 로 보인다
  (목업의 8×2 는 칸 수가 규칙과 달라 따르지 않음). 저장 좌표 · 판정은 그대로.
  보관함 칸은 가방 칸과 따로(`ps` — 가방 칸 폭의 0.6배 · 28~40pt)라 띠가 낮다(18 Pro 약 86pt). 높이가 모자라면 가방 칸이 먼저 크기를 갖고,
  띠는 엄지 줄 바로 위에 붙는다. 오른쪽 기둥 = 보관함 이름 · 빈자리에 넣기(44pt) · 세트 줄(남는 높이만큼 줄 수).
- 설명 상자 · 말풍선 대신 **설명 카드**를 보관함 띠 자리에 덮는다 — 가방 칸은 절대 가리지 않는다.
  가방 타일을 고르면 띠 전체(보관함을 잠시 가린다 — 끌기 시작하면 카드가 숨어 보관함이 다시 보이고 놓을 수 있다),
  보관함 타일을 고르면 오른쪽 기둥만(고른 칸이 보이게). 넘치면 아래 안내 줄을 빼고, 그래도 넘치면 글자를 11 → 10 → 9pt 로 줄인다.
  카드나 빈 곳을 누르면 닫힌다(카드는 누름을 삼킨다 — 아래 보관함 칸 · '빈자리에 넣기'로 새지 않음). 다른 타일을 고르면 다시 뜬다.
- 엿보기 띠(BBUI BagPeekView): 판에서 도는 콤보 경로(스냅숏 comboRoute · comboStep)를, 없으면 가방 첫 경로를 **같은 크기 가로 카드**로 한 줄에 늘어놓는다
  (가방 모양 그대로면 1×3 어퍼컷 같은 키 큰 타일 아래가 비었다). 카드 = 순서 배지(경로 색 · ★) · 이름 · 피해 · 쿨다운 · 쿨다운 막대(가방 격자와 같은 값).
  방금 친 칸 = 흰 테두리 + 밝은 바탕 + '지금' · 다음 칸 = 주황 테두리 + '다음' · 이미 친 칸 = 흐리게. 카드 폭은 폭을 나눠 84~150pt,
  84pt 보다 좁아지면 가로로 밀리고 지금 칸 근처로 옮겨 둔다. 카드가 96pt 이상이면 이름 · 수치를 14.67pt(이름 두 줄), 낮으면 11pt(이름 한 줄).
  위 글 줄 = 왼쪽 '지금 k/n · 경로 이름(· 콤보 n개)' · 오른쪽 '다음 ▶ 기술' — 좁으면 콤보 수를 빼고, 그래도 넘치면 줄인다(자르지 않음).
- 엄지 줄: 속도 · 가방 열기도 필살과 같은 80pt(위 빈 틈 없게).
- 콤보 경로선: 시트에선 웹 높이(칸의 0.26 — 이름 줄)보다 0.4칸 아래(이름 두 줄 밑)에 긋는다 — 선이 이름을 가리지 않게. classic 은 웹 그대로.
- 타일 글자(BagTileNode `text`): 화면 배율 · 줄바꿈 설정이 주석에 묻혀 안 불리던 것을 고쳤다(글자가 또렷해지고 'Punch Combo' 같은 이름이 두 줄로 접힌다 — 예전 배치도 같이 바뀜).

## 도트 디자인 토큰(Flow/PixelUI.swift)
- 글자 사다리 `PXType`(갈무리11): s 11pt · m 14.67pt · l 22pt — 3배 화면에서 글자 1px = 기기 3 · 4 · 6px.
- 간격 `PXSpace`: 4 · 8 · 12 · 16, 최소 누름 자리 `PXSpace.hit` = 44pt.
- 색: 기존 `PX` + 시트 가죽(leather …) · 필살(hot …) · 정리 중(calm …) · 판 단추(plateFill · plateLine).
- 단추 `PixelButton(kind: .plate | .brass | .hot)`: 평소 · 눌림(1.5pt 내려감 + 어두워짐 · 아래 턱 사라짐) · 끔(회색 · 흐림), 최소 44×44.
  눌리는 순간 환경값 `pixelFeedback` → `GameSession.buttonFeedback`(딸깍 + 진동 설정이 켜져 있으면 가벼운 진동).
  가방 시트의 UIKit 단추도 같은 눌림 · 피드백(`BagGridView.onButtonFeedback`).
- 게임 화면 · 매점(새 배치)을 옮겼다. 메뉴 · 결과 · 예전 배치 매점은 예전 `PixelButtonLook` · `PixelButtonStyle` 그대로.

## 개발자 스위치 · 점검
- 설정 › 개발자(버전 7번) › 레이아웃: 새 배치 / 예전 배치. 저장 키 `bbn-layout`("old" 면 예전, 없으면 새 배치) — 새 키만 더했다.
  개발자 칸을 닫으면 새 배치로 돌아간다.
- 실행 인자(DEBUG): `-bagopen [초]`(판 시작 후 시트 펼치기) · `-bagsel [stash]`(첫 타일 · stash 면 보관함 첫 타일 고르기 — 설명 카드) ·
  `-arrange`(첫 매점에서 첫 카드 → 정리 단계 · 속도 2배 · 필살 자동 · 정리에 들면 bagTouch 한 번으로 타이머를 멈춰 둔다 — 시트 자동 펼침 · '출발 ▶' 점검) ·
  `-arrangelive`(-arrange 와 같지만 bagTouch 를 안 넣어 '출발 ▶ n초 뒤 자동'이 흐른다) ·
  `-shop`(첫 매점까지 가서 멈춘다 · 속도 2배 · 필살 자동 — 매점은 시간 제한이 없다) ·
  `-layout old|new` · `-noprologue` · `-lang en`(영어 글 길이 점검).
  예: `xcrun simctl launch <기기> com.dijeong.bagboss.native -autostart -skiptalks -noprologue -bagopen 12 -bagsel`
  · 정리 단계: `… -autostart -skiptalks -noprologue -arrange`(18 Pro 에서 약 90초 뒤)
  · 매점: `… -autostart -skiptalks -noprologue -shop`(약 90초 뒤)
- 영어: 무대 오른쪽 위 '남은 초 · 적 수'는 통문장을 먼저 번역하고 앞 두 조각만 남긴다(조각은 사전에 없어 한국어가 남았다).
  구경꾼 환호 'quip:cheer'(BBSim 이 낸다)는 HUDModel.quips 에 웹 배열(와! · 대박! · 찍었어!)을 더해 열쇠가 그대로 보이지 않게 했다.

## 직접 조작 패드(2026-10-14 · 감독: 가방 = 빌드, 패드 = 조작감)
- 방향: 테트리스 가방은 어떤 기술을 넣고 어떻게 붙여 콤보 경로(케미)를 만들지 고르는 **빌드**, 패드는 그 결과를 손으로 내는 **고정 배치 조작판**.
  목업 비교(조각 그대로 · 가방 지도 · 엄지 부채꼴 · 2줄 정렬 → D 변주 4가지) 끝에 '기울인 두 줄 + 콤보 번호 + 기본기'로 정함(벌집 · 원형 배치는 낯설다).
- 화면(App Game/PadView.swift — 새 배치 · 설정 '직접 조작 패드' 켬 · 전투 중 접힌 시트 본문. 정리 단계 · 패드 끔이면 예전 엿보기 띠):
  위 띠 = 수동 n초 / 자동 칩 · 콤보 순서 칩(1 · 2 · 3 — 다음 차례 노랑) · 속도 / 왼쪽 = ◀ ▶(누르고 있으면 걷기) · ▼ 숙이기 · 필살(게이지) /
  오른쪽 = 기울인 두 줄 — 아래 줄 = 콤보 경로 ①②③(왼→오, 큰 버튼) + 오른쪽 끝 엄지 자리 가장 큰 **기본기** · 위 줄 = 나머지 기술(작게). 기술 버튼은 최대 6.
  버튼은 손가락이 닿는 순간 낸다(뗄 때가 아니다) · 가벼운 진동. 쿨타임 = 12시부터 시계 방향 그늘 + 남은 초 · 다음 차례 = 노란 테두리 맥박 ·
  앞에서 적이 공격을 준비하면 기본기가 빨간 '받아치기' · 큰 공격이 오면 ▼ 숙이기 테두리가 주황. 왼손 배치(설정)면 좌우를 뒤집는다.
  저장: 'bbn-pad'("0" = 끔 — 기본 켬) · 'bbn-pad-left'("1" = 왼손). 새 키만 더했다.
- 규칙(BBSim World+NativePad · SimIntent.pad · 스냅숏 pad): 아무 패드 입력이나 받으면 수동 2.5초(누르고 걷는 동안 유지) — 그동안 자동 AI 는 쉬고 패드가 조종,
  손을 떼고 2.5초 뒤 다시 자동. 입력 버퍼 0.25초(움직일 수 있는 틱에서만 나이를 센다 — 타격 정지 동안 늙지 않는다) · 타격(큐)이 이미 나간 동작의 회복 칸은
