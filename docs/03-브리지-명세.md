# 03 · 브리지 명세 (v1)

웹(게임) ⇄ 네이티브(Swift 셸) 사이의 약속. 구현: `web/app/bridge.js` ⇄ `ios/BagBoss/Bridge/BridgeRouter.swift`.
메시지를 바꾸면 이 문서 · 두 구현 · `tools/test/bridge_test.py`를 **함께** 고친다.

## 주입 순서 (documentStart, 메인 프레임, page world)
1. 머리말: `window.__BAGBOSS_CFG__ = {debug, perf, haptics, saveMirror, keyPrefix}` · `window.__BAGBOSS_SAVE__ = {key: string}`
2. `bridge.js` — `window.NativeBridge` 생성, `localStorage` 복원 · 감싸기, `navigator.vibrate` 폴리필, rAF 측정 시작
3. 게임 스크립트(`index.html`) — 아무것도 모른 채 평소대로 실행

게임 코드는 즉시 실행 함수 안에 있어 전역을 직접 못 읽는다. bridge.js는 개발 훅 `window.__dotlab`만 쓴다(`GS` · `openMenu` · `saveRun` · `meta` · `snd` · `isPaused` · `lang`).

## 봉투
```js
// 웹 → 네이티브 (WKScriptMessageHandlerWithReply · 이름 "bagboss")
const reply = await window.webkit.messageHandlers.bagboss.postMessage({ v: 1, type: 'save.put', payload: {...} });
// 네이티브 → 웹 (callAsyncJavaScript, page world)
return await NativeBridge._native({ type: 'app.pause' });
```
- `v`: 봉투 버전(지금 1). 깨지는 변경이면 2로 올리고 라우터가 둘 다 받게 한다.
- 실패: 네이티브가 `replyHandler(nil, "이유")` → 웹 Promise reject → bridge.js `send()`가 삼키고 `null`.
- 웹은 네이티브 응답을 기다리지 않아도 되게 짠다(fire-and-forget 기본, 필요한 곳만 await).

## 웹 → 네이티브
| type | payload | 응답 | 언제 |
|---|---|---|---|
| `app.ready` | `{restored: string[], dpr, w, h, lang, canvas: "1110x624", webgl2}` | `{native:true, version:1}` | window `load` 직후 1회 |
| `save.put` | `{entries: {key: string \| null}}` (null = 삭제) | `{ok:true, n}` | `dotlab*` 키 변경 후 400ms 모아서 · `app.pause` 때 즉시 |
| `haptic` | `{pattern: number[]}` — `[ms]` 또는 `[울림, 쉼, 울림, …]` | — | 게임 `buzz()` → `navigator.vibrate()` |
| `perf.sample` | `{fps, p50, p95, max, long, scene, px}` | — | 1초마다 (`CFG.perf`) |
| `gl.lost` | `{scene, px}` | — | 무대 캔버스 `webglcontextlost` |
| `log` | `{level: 'warn'\|'error', msg, src?, stack?}` | — | window error · unhandledrejection · (debug) console.warn/error |

`scene` 값: `boot` · `title` · `dojo` · `tower:<층>` · `<state>:<stageIdx>.<ci>` (예 `fight:2.4`)

## 네이티브 → 웹 (`NativeBridge._native({type})`)
| type | 웹이 하는 일 | 결과 |
|---|---|---|
| `app.pause` | 싸우는 중이면 `openMenu('run')`(메뉴 = 일시정지 화면) → `saveRun()` → 메타 기록을 localStorage에 → 대기 중 `save.put` 즉시 플러시 | 마지막 `save.put` 응답 |
| `app.resume` | AudioContext가 멈춰 있으면 `resume()` · 프레임 측정 기준 초기화 | `true` |
| `save.flush` | 대기 중 `save.put` 즉시 | 응답 또는 null |
| `perf.reset` | 측정 창 초기화 | `true` |
| `memory.warning` | `log`(warn)로 장면과 함께 되돌려 보냄 | `true` |

셸이 부르는 시점: `sceneWillResignActive` → `app.pause` · `sceneDidBecomeActive` → `app.resume` · `sceneDidEnterBackground` → `app.pause` 후 응답 오면 `SaveStore.flush()`(백그라운드 작업 안) · 오디오 인터럽트 종료 → `app.resume` · 메모리 경고 → `memory.warning`.

## 저장 키 (localStorage · 웹이 원본, 네이티브 파일은 백업)
| 키 | 내용 | 비고 |
|---|---|---|
| `dotlab-subway-meta-v1` | 메타 진행(기록 · 해금 · 도감 · 타워 기록 · 야근 단계) | **가장 중요** |
| `dotlab-run-v1` | 판 이어 하기(칸마다 자동 저장) | |
| `dotlab-opt` | 옵션(스킨 · 진동 · 자동 필살기 · 개발자 설정 …) | 스킨 결제 연동 대상 |
| `dotlab-snd` | 볼륨 · 음소거 | |
| `dotlab-lang` | `ko` / `en` | 시작 시 동기 읽기 |
| `dotlab-cc` | 커스텀 콤보 | |
| `dotlab.graph.v4` · `dotlab.poses.v2` · `dotlab-poseEdits` | 엔진 실험실 · 자세 편집(개발) | |

네이티브 파일: `Application Support/BagBoss/save.json` = `{v:1, updatedAt, keys:{…}}` · 1초 모아 원자적 쓰기.
복원 규칙: 시작 시 스냅숏을 주입 → **웹에 그 키가 없을 때만** 써 넣는다(웹 값이 있으면 웹 우선).
→ 2단계에서 iCloud 동기화를 붙이면 '어느 쪽이 최신인가' 규칙이 필요하다(메타의 갱신 시각 필드 추가 제안).

## 햅틱 매핑 (Haptics.swift · 초안)
| 게임 호출 | 쓰임 | 매핑 |
|---|---|---|
| `buzz(16)` | 주인공 타격이 넘어뜨림 · 치명타 · 띄우기일 때 | light 0.75 |
| `buzz(28)` | 위의 큰 치명타(bigCrit) | medium 0.85 |
| `buzz(25)` | **주인공이 맞을 때마다** (가장 잦음) | medium 0.85 |
| `buzz(50)` | 'KA-BOOM!' 효과음 연출 | heavy 0.9 |
| `buzz(70)` | 두목 등장 | heavy 1.0 |
| `buzz([40,30,60])` | 필살기 | heavy 0.9 → (70ms 뒤) heavy 0.9 |
| `buzz([50,30,80])` | 차 부수기 | heavy → (80ms 뒤) heavy 1.0 |
- 45ms 안의 연속 호출은 한 번으로 뭉갠다. 게임 옵션 `OPT.vibe === false`면 게임이 애초에 부르지 않는다.
