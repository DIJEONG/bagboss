## 단계 A — 조각 분리 (동작 변화 0, 1.5단계 첫 작업)
- `python3 tools/split_web.py split` → `web/src/_head.html · 00-i18n.js … 50-mobile-dev.js · _tail.html · ORDER.txt` (조각 51개 + 머리/꼬리)
- `python3 tools/split_web.py join` → 순서대로 이어 붙여 `web/index.html` 재생성. **원본과 바이트 단위로 같다**(검증 완료: sha `20ef9c52ad3f72a2` 왕복 동일)
- 조각 파일은 단독으로 유효한 JS가 아니다(함수 몸통의 일부). 대신 얻는 것:
  - 파일 단위 탐색 · 작은 diff · Claude Code가 1.5MB 대신 30~60KB 조각만 읽고 고칠 수 있음
  - 조각별 소유 · 리뷰 단위
- 주의: 분리 이후에는 `web/src/`가 정본이 된다. 지금은 게임을 클라우드 작업 세션에서 단일 HTML로 고쳐 내려오므로, **정본을 옮기는 시점을 한 번에 합의**해야 한다(그 전까지는 `verify`만 돌려 경계표를 최신으로 유지).
- 원본이 바뀌어 경계가 밀리면 `split_web.py --suggest`가 각 경계 근처의 섹션 머리줄 후보를 보여 준다 → `modules.json`의 `start`만 고친다.

## 단계 B — 정식 호스트 API (1.5단계)
게임 쪽에 네이티브 셸 전용 창구를 하나 만든다(`__dotlab` 개발 훅 의존 끊기). 제안 형태:
```js
window.BAGBOSS_HOST = {
  version: 1,
  pause(reason), resume(),            // 메뉴 열기 대신 진짜 일시정지(오디오 · 시간 정지)
  save(),                              // saveRun + metaSave를 한 번에, Promise
  state(),                             // { scene, state, stage, car, floor, hp, inRun }
  setSkinOwned(id, owned),             // 스킨 결제(StoreKit) 결과 반영
  onEvent(fn),                         // 게임 → 셸 이벤트(판 끝 · 두목 처치 · 타워 기록 · 결과 화면)
};
```
bridge.js는 `BAGBOSS_HOST`가 있으면 그것을, 없으면 지금처럼 `__dotlab`을 쓰게 바꾼다(하위 호환).

## 단계 D — 진짜 모듈로 (필요할 때만, 잎부터)
의존이 적은 잎부터 ES 모듈로 꺼낸다. 꺼낼 때마다 회귀 테스트.
1. `00-i18n.js`의 `EN_DICT`(순수 데이터 75KB) → `i18n/en.json` + 로더
2. `35-audio.js`(WebAudio 합성 — 바깥 의존: 게임 상태 몇 개) → `audio.js` (입력: 이벤트 · 볼륨)
3. 절차 아트 생성기(`03~11-art-*`) — 입력이 시드 · 팔레트뿐인 함수부터
4. 게임 규칙(`22~30`)과 UI(`31~47`)는 상태 공유가 많아 마지막. 상태 객체(`GS`)를 명시적으로 넘기는 형태로.
D는 출시에 필수가 아니다. 유지보수 비용이 실제로 아플 때 한다.
