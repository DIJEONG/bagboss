## 1. 지금 구조에서 확인한 사실 (이식을 좌우하는 것만)

### 1.1 렌더
- 장면마다 내부 해상도가 다르다(`SCN`, 18). **지하철 480×270**이고, 세로 화면에서는 `VW = H·4/3 = 360` 폭으로 잘라 쓴다. 장면이 바뀌면 렌더 타깃(RT)을 모두 다시 만든다.
- 패스:
  1. **G-버퍼**: MRT 2장(RGBA8) + depth16.
     - `gInfo` = 재질 · 톤 · 발광 · 마스크/파츠 번호
     - `gNorm` = nx · ny · 깊이 · 높이
     - 그림자는 G 채널에 곱하기 블렌드로 넣는다.
  2. **합성(조명)**:
     - 광원 최대 8개(점 · 스폿 · 방향), 림 조명, 8칸 레이마칭 높이 그림자
     - 팔레트 LUT를 6단으로 끊고 Bayer · 재질별 1비트 디더
     - 캐릭터 선
  3. **후처리**: 블룸(½ 해상도, 블러 2회 왕복), 충격파 굴절 최대 4개, 볼류메트릭 원뿔 최대 6개, 반사 · 안개 · 비 · 색 보정, 임팩트 프레임 반전. 마지막에 **채널당 24단 + Bayer4 양자화**.
  4. **블릿**: sharp-bilinear 확대, 정수배 스냅(94% 기준), 줌 펀치.
- 캐릭터는 두 종류다.
  - 2D 파츠 리그: 파츠마다 32방향 RotSprite를 미리 굽는다.
  - 3D 로우폴리 리그: `prism`. 매 프레임 CPU에서 삼각형을 만들고 최대 12k개.
- 모든 텍스처 읽기가 `texelFetch`(정수 좌표)라서 Metal `.read()`로 1:1 대응한다. 프로그래머블 블렌딩도 필요 없다.

### 1.2 시간 · 결정성
- 게임 로직은 **가변 dt**이고, 애니메이션만 고정 스텝이다(게임 모드 20fps · 엔진 실험실 12fps — setMode 가 바꾼다). 실제 **피해는 애니메이션 큐(`onCue`) 콜백에서 들어간다** → 판정 타이밍이 포즈 시퀀스(ms)에 묶여 있다.
- 규칙에서 `Math.random`이 약 100곳, 엔진에서 약 12곳 쓰인다. 시드 RNG를 쓰는 곳은 `twDaily` 하나다.
- 벽시계에 의존하는 곳: `setTimeout` 여러 곳, `performance.now()`(피해 숫자, 눈 적응), `slowT`. → 지금은 리플레이나 결정적 테스트가 불가능하다.

### 1.3 상태
- `GS` 하나에 판 진행 · 전투 · 가방 · 점수 · 타워 · **연출 값**(`flash`, `zoomK`, `oneBit`, `adA` …)이 섞여 있고, 30개 조각이 직접 바꾼다.
- GS 밖에도 가변 상태가 있다: `TR`(열차), `STAGE/LINE/STOPS`, `scene`, `freeze/shakeAmp/comicT/IMPF`, 이펙트 배열(`HITFX`, `DPOPS`, `COMIC`, `sparks`, `dusts`).
- 모드 플래그(`GS.prologue/tower/demo/bonus/cine/talk/skinPv/devRun`)가 수십 곳에서 분기를 만든다.

### 2.3 시뮬레이션 계약
```swift
public struct SimInput { var intents: [Intent] }          // tap(side, t) · duck · special · speed · bagMove(...) · menu…
public enum SimEvent { case hit(HitLanded), blocked(...), foeDowned(...), sfx(SfxCue), say(Bark),
                       camera(CameraKick), haptic(HapticCue), bagChanged, waveSpawned(...), arrived(...),
                       bossAppear(...), tower(TowerEvent), runEnded(...), metaDirty, … }
public final class Sim {
  public private(set) var state: GameState                // 값 타입 트리
  public init(content: Content, seed: UInt64, mode: ModeConfig)
  public mutating func step(_ input: SimInput) -> [SimEvent]  // 1틱 = 1/60초(시뮬레이션 시간)
}
```
- **시간**
  - 틱 = 1/60초. 애니메이션 칸(게임 20fps)은 3틱마다 한 번 넘어간다.
  - `playSpeed` · 슬로 · 가방 슬로 · 히트스톱은 "이번 프레임에 몇 틱을 돌릴지"와 액터별 정지 틱으로 표현한다. 벽시계를 쓰지 않는다.
  - `setTimeout`은 전부 Sim 안의 예약 큐로 바꾼다(`schedule(afterTicks:, event)`).
- **입력 지연**: 저스트 창이 160ms다. 터치 타임스탬프(`UITouch.timestamp`)를 시뮬레이션 시간으로 바꿔서 Intent에 싣는다. 판정은 **그 시각 기준**으로 한다.
- **난수**: `rngRule`(판정 · 드롭 · AI)과 `rngFx`(파티클 · 흔들림 지터 · 소리 변주)를 분리한다. 데일리 모드는 날짜 시드로 `rngRule` 전체를 고정한다. 웹판은 매점과 탑승 순서만 고정했지만, 이번에는 전투도 같게 만든다.
- **연출 값 분리**: `flash, zoomK, zoomC, shoveX, invF, oneBit, adA, fade, wipe, lbox …`는 GS에서 빼낸다. Sim은 `CameraKick` · `ScreenFlash` · `Blackout(on)` 같은 **이벤트나 의도 상태**만 내보내고, 실제 보간 값은 Presentation이 가진다.
- **모드**: 지금 곳곳에 흩어진 `if (GS.tower) … else if (GS.bonus) …` 분기를 `protocol GameMode { func step(...) }` 구현체로 나눈다. 판 공통 시스템(전투 · 가방 · 콤보)은 모드가 조합해서 쓴다.

### 2.4 애니메이션과 판정 타이밍
지금은 피해가 들어가는 순간이 "포즈 시퀀스의 큐 칸"에 묶여 있다. 손맛을 그대로 지키려고 **이 구조는 유지한다.** 다만 시퀀스 재생을 렌더에서 떼어 BBAnim으로 옮기고, Sim이 그것을 돌린다.
- Sim은 액터마다 `SequencePlayer`(현재 동작 · 칸 · 남은 ms · 큐 목록)를 가진다. 큐 칸에 도달하면 `onCue` → 규칙(피해 등)이 실행된다.
- 렌더는 Sim 스냅숏의 (동작, 칸, 진행률)로 `PoseEval`을 불러 보간 포즈를 계산한다. 보간은 그리기 전용이라 판정에 영향이 없다.
- `atkStartup` · `timeToCue` · `FOE_TELL`은 시퀀스 데이터에서 계산한다. 따로 손으로 적은 표를 두지 않는다.

| Composite | 조명 · 팔레트 램프 · 디더 · 캐릭터 선 | `rgba8Unorm`(linear 샘플) | 프리셋 6 + PRELUDE |
| Bright/Blur | 블룸 ½ 해상도 | `rgba8Unorm`×2 | runPost |
| Post | 굴절 · 원뿔 · 반사 · 안개 · 비 · 색 보정 · 반전 · 24단 양자화 | `rgba8Unorm` | FS_POST |
| Overlay | 피해 숫자 · HITFX · 코믹 · 말풍선 · 컷인 · SP 게이지 · 두목 바 · 문 전환 | 화면 해상도(UI 3배 격자) | `#ui` 캔버스 |
| Blit | sharp-bilinear · 정수배 스냅 · 줌 · 세로 크롭 | drawable | FS_BLIT |

- 장면 렌더 설정(`SceneRenderConfig`)은 내부 해상도 · 프리셋 · 후처리 기본값을 데이터로 갖는다. 장면별 광원 · FX(`subwayLights/towerFX/dojoFX` …)는 Presentation이 상태 스냅숏에서 만들어 렌더러에 넘긴다. **렌더러는 GS를 읽지 않는다.**
- 3D 리그 정점 생성은 Swift SIMD로 CPU에서 하고 매 프레임 버퍼에 쓴다(삼중 버퍼링). 뒷면 판정 · Z 공식(`.9-footY/300-p.z/600`)은 원본 그대로 옮긴다.
- 정확도: Y축 뒤집기 · `gl_FragCoord` 원점 · Bayer 위상을 맞춘다. §4의 렌더 비교 테스트로 확인한다.
- 120Hz: 시뮬레이션은 60Hz 고정이고, 렌더는 디스플레이 주기에 맞춰 상태를 보간하거나 같은 프레임을 반복한다. 우선 60에 고정하고 측정 후에 정한다.

### 2.6 아트 · 콘텐츠 파이프라인 (JS가 "콘텐츠 컴파일러")
```
web/src/*.js ──node 하네스(01~11, 37, 39, 43 + pillowField)──▶ SPR 전체
      │                                                    ├─▶ atlas_a.png (mat, tone, emit, 255)
      │                                                    ├─▶ atlas_n.png (nx, ny, mask, rel)
      │                                                    ├─▶ palettes.png (3 × 80재질 × 6단)
      │                                                    └─▶ atlas.json (이름 → rect · 피벗 · mask, CITY_CFG.layers, NOIR_LIGHTS, SB/TWR/STN/CAR_CONCEPTS 상수)
      ├──content.mjs──▶ items.json · enemies.json · lines.json · tower.json · kits.json · poses.json · sequences.json · talk.json …
      ├──strings.mjs──▶ Localizable.xcstrings (원문 ko 키, EN_DICT 1,241 + KE() 쌍, 템플릿 {0} → %1$@)
      └──sfx.mjs──────▶ Sfx/*.caf (고정 효과음, 변주 3~4개씩) + 기준 파형(실시간 합성 회귀용)
```
- 생성기 전체 실행 시간은 Mac node에서 445ms다. 스프라이트 3,085장이고 약 6Mpx이며, 그중 회전판이 2,531장이다. 아틀라스는 2048 폭이고, 아래 1024줄(불러온 원화 영역)은 쓰지 않는다.
- 람다가 들어 있는 데이터는 자동 추출이 안 된다. `LINKS`의 술어, `COND`, `TALK`의 `onShow`가 그렇다. 이런 항목은 추출기가 **목록을 뽑아 보고**하고, Swift 쪽에서 `enum` + 손으로 쓴 구현으로 옮긴다.
- 웹 원본이 계속 바뀌는 동안에는 `extract`를 다시 돌려 JSON과 PNG의 diff를 리뷰 단위로 삼는다.

### 2.8 오디오 · 진동
- **AVAudioEngine 그래프**: `mixer ← DynamicsProcessor ← {music, sfx, amb}`. 웹 그래프와 같은 모양이다.
- **실시간 합성**(`AVAudioSourceNode`, 오디오 스레드):
  - 열차 루프 8종: 속도 · 제동 · 다리 · 문에 연동
  - 차 경보
  - 대사 `blip`: 모음 → 음높이
  - `floor(p)`, `clack(k)`
  - **재즈 시퀀서**: D단조 ii-V-i, 92/110/124 BPM, 스윙. 게임에서 받는 입력은 `intensity`, `buskOn` 두 개로 줄인다.
- **굽기**: 나머지 효과음 약 25종(`hit3`은 tier × crit × air 조합). 음높이 변화는 재생 rate로 낸다.
- **진동**: `HapticCue` 이벤트 → Core Haptics. 매핑은 docs/03 표를 계승하고, 45ms 안에 겹치면 하나로 합친다.

### 2.9 저장 · 이관
- `MetaState`/`RunSave`/`Options`/`SoundOptions`는 **웹 v1 JSON과 같은 키 · 모양**으로 Codable을 쓴다. 모르는 필드는 보존한다(`[String: JSONValue]` 여분 버킷).
- 이관 경로: 웹 셸 앱(1단계)이 이미 `Application Support/BagBoss/save.json`(`{v, updatedAt, keys}`)에 미러를 쓰고 있다. **같은 번들 ID로 네이티브 앱을 내면** 첫 실행 때 이 파일을 읽어 가져온다. 셸을 출시하지 않으면 이관 대상이 없으니 이 단계는 건너뛴다.
- 버전: 네이티브 저장은 `v:2` + `updatedAt`(iCloud 충돌 해결용)으로 저장한다. v1은 읽기만 한다.

### 2.10 디버그 · 테스트 API (`__dotlab` 계승)
`#if DEBUG`에서 `DebugConsole`(앱 안 패널 + XCUITest `launchArguments` + URL 스킴) 하나로 모은다.
- 상태 스냅숏 JSON: towerSt, bagSt, combo, jugInfo, spcState, meta 등에 해당.
- 시나리오 점프: 노선 · 칸 · 가방 ★ · 무적 · 타워 층 · 보너스 · 프롤로그.
- 시간 제어: 속도 · 정지 · 한 틱씩 · 시드 고정.
- 자동 입력 봇: justBot, setAuto.
- 성능 HUD와 CSV(`PerfMonitor` 재사용). docs/04 시나리오 S1~S6을 네이티브에서도 같은 이름으로 돈다.

## 4. 같게 동작하는지 확인하는 법 (웹판 = 오라클)
웹판은 결정적이지 않아서 "같은 판을 끝까지 비교"할 수는 없다. 대신 층마다 비교한다.
1. **순수 함수 픽스처(정확 일치)**: node 하네스로 JS 함수를 직접 불러 입력 → 출력을 JSON으로 덤프하고 Swift 테스트로 대조한다.
   - 대상: `shapeOf/canPlace/findSpot/stashPut` · `sStats/pv/condOK` · `computeSets` · `routeFrom/routesOf/comboName` · `damage`(RNG를 고정값으로 대체) · `jugStep` · `curPose/lerpPose/solveLeg/gaitPose` · `twWeight` · 점수 · 보상 공식 · `tr()` 결과
2. **렌더 스냅숏(허용 오차)**: Playwright로 웹판의 고정 장면(지하철 칸 n, 타워 층 n, 고정 포즈 · 고정 시간)을 캡처하고, Swift 오프스크린 렌더와 픽셀을 비교한다. 양자화 단계가 같으므로 차이는 거의 0이어야 한다.
3. **효과음 파형**: `sndRender` 훅이 낸 기준 파형과 Swift 합성 결과를 비교한다(스펙트럼 · 엔벨로프 허용 오차).
4. **체감 · 통계**: 같은 노선 · 가방 · 자동 전투로 N판 돌려 클리어 시간 · 받은 피해 · 콤보 수 분포를 비교한다(DebugConsole + 웹 `__dotlab`). 바뀐 시간 모델(고정 스텝) 때문에 생기는 차이를 여기서 잡는다.
5. **손맛**: 저스트 성공률 · 가방 드래그 지연은 실기기에서 사람이 판정한다. docs/04 체크리스트를 확장해 쓴다.
